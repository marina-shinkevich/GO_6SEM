Чтобы магия сработала и страница с документацией открылась, преподавателю нужно объяснить порядок действий в консоли:
1. Установка генератора Swag Сначала мы устанавливаем утилиту командной строки swag, которая будет читать наши комментарии: go install github.com/swaggo/swag/cmd/swag@latest
2. Обновление зависимостей Так как мы используем внешние пакеты (Iris и Swagger), нужно скачать их: go mod tidy.
3. Генерация файлов (Главный шаг) Мы вводим в консоли команду: swag init. Эта утилита просканирует все файлы .go в нашем проекте, найдет комментарии, начинающиеся с символа @, и автоматически создаст папку docs, внутри которой будут лежать файлы: docs.go, swagger.json и swagger.yaml. Именно они содержат структуру нашего API, которую и отрисует браузер.

1. Что такое kataras/iris и зачем он нужен? Это один из самых быстрых сторонних веб-фреймворков для языка Go. 
В отличие от gorilla/mux, который является просто маршрутизатором, Iris — это полноценный фреймворк, который 
предоставляет контекст (iris.Context), содержащий десятки встроенных методов (например, ctx.JSON(list) 
автоматически сериализует структуру, ставит правильные заголовки и отправляет ответ клиенту).
2. Зачем нужны разные блоки комментариев?

    Глобальные (@title, @version, @host) перед func main() — задают заголовок всей веб-страницы документации и базовый адрес сервера.
    Маршрутные (@Summary, @Produce json, @Success, @Router) перед обработчиком — рассказывают Swagger'у, какой метод (GET/POST) использует эта функция, по какому пути она доступна, и, самое главное, что она возвращает в случае успеха (например, HTTP 200 и массив объектов Celebrity).
    Модельные (@Description) внутри структуры — описывают назначение каждого конкретного поля, чтобы клиент понимал, что значит поле id или fullname.

3. Как проверить, что всё работает? После запуска сервера go run ., 
достаточно открыть в браузере адрес http://localhost:3001/docs/index.html . Там отобразится графический 
интерфейс Swagger UI. В нем можно будет не только почитать описание ваших методов, но и нажать кнопку 
"Try it out" (Попробовать), чтобы прямо из браузера отправить тестовый запрос к вашему API и увидеть результат.






package main

import (
	"strconv" // Пакет для конвертации типов (нужен для перевода int ID в строку при удалении)

	// Подключаем современный и быстрый веб-фреймворк Iris для построения HTTP-сервера
	"github.com/kataras/iris/v12"

	// Подключаем пакеты для интеграции Swagger-документации в Iris
	"github.com/iris-contrib/swagger/v12"
	"github.com/iris-contrib/swagger/v12/swaggerFiles"

	// Важный пустой импорт (_). Нам не нужны функции этого пакета напрямую в коде, 
	// но этот импорт запускает функцию init() внутри пакета docs, которая регистрирует 
	// сгенерированную утилитой swag спецификацию нашего API.
	_ "rest/docs"
)

// === 1. МОДЕЛИ ДАННЫХ И ХРАНИЛИЩЕ ===

// Celebrity — структура, описывающая сущность "Знаменитость".
// Аннотации @Description используются генератором swag для отображения схемы в Swagger UI.
// @Description Модель знаменитости.
type Celebrity struct {
	// Использование JSON-тегов `json:"id"`. Они указывают сериализатору, 
	// что в JSON-формате поле должно быть со строчной буквы ("id"), а не с заглавной ("Id").
	// @Description Уникальный идентификатор знаменитости
	Id int `json:"id"`

	// @Description Полное Имя знаменитости (обязательное поле)
	FullName string `json:"fullname"`
}

var (
	// Глобальный слайс (динамический массив) структур Celebrity.
	// Выступает базой данных в оперативной памяти (In-Memory хранилище).
	// Данные живут ровно столько, сколько запущен процесс сервера.
	celebrities = []Celebrity{
		{Id: 1, FullName: "John Doe"},
		{Id: 2, FullName: "Jane Smith"},
	}
	
	// Переменная-счетчик для имитации механизма AUTOINCREMENT (как в реляционных БД).
	// Каждому новому объекту будет присваиваться текущее значение, после чего оно увеличится.
	nextID = 3
)

// === 2. ОБЩЕЕ ОПИСАНИЕ API ===
// Данные аннотации формируют метаданные на главной странице документации Swagger.

// @title Celebrities API
// @version 1.0
// @description Полное REST API для управления списком знаменитостей с использованием локального хранилища.
// @host localhost:3001
// @BasePath /
func main() {
	// Инициализируем новое приложение Iris
	app := iris.New()

	// Регистрируем эндпоинт для Swagger UI. 
	// Конструкция {any:path} — это wildcard-роутинг Iris, перенаправляющий любые подпути 
	// (например, /docs/swagger-ui.css) в обработчик статических файлов документации.
	app.Get("/docs/{any:path}", swagger.WrapHandler(swaggerFiles.Handler))

	// Группируем маршруты по префиксу "/celebrities". 
	// Это избавляет от дублирования путей и логически разделяет подсистемы (Паттерн Route Grouping).
	cRoute := app.Party("/celebrities")
	{
		// Привязываем методы HTTP-запросов и пути к конкретным функциям-обработчикам (handlers)
		cRoute.Get("/", getAllCelebrities)          // Получить список всех знаменитостей
		cRoute.Get("/{id:int}", getCelebrityByID)   // Получить одну запись по ID (с валидацией параметра на тип int)
		cRoute.Post("/", createCelebrity)           // Создать новую запись
		cRoute.Put("/{id:int}", updateCelebrity)    // Обновить существующую запись по ID
		cRoute.Delete("/{id:int}", deleteCelebrity) // Удалить запись по ID
	}

	// Запуск веб-сервера на порту 3001
	app.Listen(":3001")
}

// === 3. ОБРАБОТЧИКИ REST ОПЕРАЦИЙ ===

// getAllCelebrities godoc
// @Summary Получить всех знаменитостей
// @Description Возвращает полный список знаменитостей
// @Produce json
// @Success 200 {array} Celebrity
// @Router /celebrities [get]
func getAllCelebrities(ctx iris.Context) {
	// Функция ctx.JSON автоматически маршалирует (конвертирует) слайс Go-структур в JSON-строку 
	// и отправляет клиенту вместе с HTTP-статусом 200 OK и заголовком Content-Type: application/json.
	ctx.JSON(celebrities)
}

// getCelebrityByID godoc
// @Summary Получить знаменитость по ID
// @Description Возвращает одну знаменитость по её числовому идентификатору
// @Produce json
// @Param id path int true "ID Знаменитости"
// @Success 200 {object} Celebrity
// @Failure 404 {string} string "Celebrity not found"
// @Router /celebrities/{id} [get]
func getCelebrityByID(ctx iris.Context) {
	// Извлекаем параметр id из URL. Ошибку игнорируем через `_`, 
	// так как Iris на уровне роутера `{id:int}` гарантирует, что там находится целое число.
	id, _ := ctx.Params().GetInt("id")

	// Классический линейный поиск O(N) по слайсу
	for _, c := range celebrities {
		if c.Id == id {
			ctx.JSON(c) // Если совпадение найдено, отдаем объект и прерываем выполнение функции
			return
		}
	}

	// Если цикл завершился и совпадений нет — выставляем статус 404 и пишем текстовую ошибку
	ctx.StatusCode(iris.StatusNotFound)
	ctx.WriteString("Celebrity not found")
}

// createCelebrity godoc
// @Summary Создать новую знаменитость
// @Description Принимает JSON без ID, генерирует ID автоматически и сохраняет в массив
// @Accept json
// @Produce json
// @Param celebrity body Celebrity true "Данные знаменитости"
// @Success 201 {object} Celebrity
// @Failure 400 {string} string "Bad Request"
// @Router /celebrities [post]
func createCelebrity(ctx iris.Context) {
	var newCelebrity Celebrity
	
	// Считываем JSON из тела запроса (Request Body) и парсим его в структуру newCelebrity.
	// Если структура JSON нарушена, функция вернет ошибку, и мы прервем выполнение.
	if err := ctx.ReadJSON(&newCelebrity); err != nil {
		ctx.StatusCode(iris.StatusBadRequest) // Статус 400 Bad Request
		ctx.WriteString("Invalid JSON input")
		return
	}

	// Бизнес-логика присвоения уникального ID
	newCelebrity.Id = nextID
	nextID++ // Увеличиваем глобальный счетчик для последующих записей
	
	// Добавляем созданный объект в конец глобального слайса
	celebrities = append(celebrities, newCelebrity)

	// Возвращаем статус 201 Created (стандарт для успешного создания сущностей в REST) и сам объект
	ctx.StatusCode(iris.StatusCreated)
	ctx.JSON(newCelebrity)
}

// updateCelebrity godoc
// @Summary Обновить существующую знаменитость
// @Description Находит знаменитость по ID и перезаписывает её данные
// @Accept json
// @Produce json
// @Param id path int true "ID Знаменитости"
// @Param celebrity body Celebrity true "Новые данные знаменитости"
// @Success 200 {object} Celebrity
// @Failure 400 {string} string "Bad Request"
// @Failure 404 {string} string "Celebrity not found"
// @Router /celebrities/{id} [put]
func updateCelebrity(ctx iris.Context) {
	id, _ := ctx.Params().GetInt("id")
	var updatedCelebrity Celebrity

	// Читаем новое состояние объекта из тела запроса
	if err := ctx.ReadJSON(&updatedCelebrity); err != nil {
		ctx.StatusCode(iris.StatusBadRequest)
		ctx.WriteString("Invalid JSON input")
		return
	}

	// Ищем элемент по ID, используя индекс `i`
	for i, c := range celebrities {
		if c.Id == id {
			// Перезаписываем поля существующего элемента в слайсе. 
			// ID не меняем, так как он зафиксирован в URL.
			celebrities[i].FullName = updatedCelebrity.FullName
			updatedCelebrity.Id = id // Гарантируем, что клиенту вернется объект с правильным ID
			
			ctx.JSON(celebrities[i])
			return
		}
	}

	ctx.StatusCode(iris.StatusNotFound)
	ctx.WriteString("Celebrity not found")
}

// deleteCelebrity godoc
// @Summary Удалить знаменитость
// @Description Удаляет знаменитость из локального массива по ID
// @Produce json
// @Param id path int true "ID Знаменитости"
// @Success 200 {string} string "Celebrity deleted successfully"
// @Failure 404 {string} string "Celebrity not found"
// @Router /celebrities/{id} [delete]
func deleteCelebrity(ctx iris.Context) {
	id, _ := ctx.Params().GetInt("id")

	for i, c := range celebrities {
		if c.Id == id {
			// Механизм удаления элемента из слайса в Go.
			// `celebrities[:i]` — берет срез элементов ДО удаляемого (индекс i не включается).
			// `celebrities[i+1:]...` — берет срез элементов ПОСЛЕ удаляемого до конца массива.
			// `...` (variadic) распаковывает правый срез, чтобы передать его элементы по отдельности в append.
			celebrities = append(celebrities[:i], celebrities[i+1:]...)
			
			// Формируем текстовый ответ. Числовой id приводим к строке с помощью strconv.Itoa.
			ctx.WriteString("Celebrity with ID " + strconv.Itoa(id) + " deleted successfully")
			return
		}
	}

	ctx.StatusCode(iris.StatusNotFound)
	ctx.WriteString("Celebrity not found")
}






Что такое Iris?
Iris — это готовый веб-фреймворк для языка Go. Если проводить аналогию, это как набор строительных лесов и 
инструментов для быстрого создания сайтов и API.

Зачем нужен: На чистом Go (пакет net/http) писать веб-серверы можно, но приходится вручную разбирать
 URL-адреса, проверять типы данных, настраивать CORS и сессии. Iris берет эту рутину на себя. Он дает
  удобный роутинг (например, группировку маршрутов app.Party), встроенную валидацию параметров (вроде 
  {id:int}) и высокую скорость работы.

Что за папка docs и что там хранится?
Папка docs — это каталог, который автоматически генерируется специальной утилитой swag
 (Swagger) на основе комментариев в вашем коде (тех самых, что начинаются с // @title, // @Router).

Что в ней хранится:

Главный файл документации (обычно docs.go, а также swagger.json или swagger.yaml).
Внутри этих файлов на специальном структурированном языке описано абсолютно всё ваше API:
 какие есть эндпоинты, какие HTTP-методы они принимают (GET, POST), какие параметры ждут на
  вход и какие JSON-ответы выдают.

Зачем она нужна в проекте:
Она нужна, чтобы развернуть интерактивную веб-страницу Swagger UI (по адресу /docs/index.html). Благодаря 
этой папке любой фронтенд-разработчик или тестировщик может зайти на сайт проекта, увидеть красивую
интерактивную карту вашего API и прямо в браузере протестировать любой запрос.
